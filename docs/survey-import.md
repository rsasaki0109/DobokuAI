# 横断測量CSVの取込み

横断面エディタでUTF-8 CSVを選択し、高さの解釈・標高系・水平座標を指定して検証します。
プレビューは現在のモデル・保存済みプロジェクト・計算履歴を変更しません。
「内容を確認して全測点を置換・施工案をクリア」で反映し、流量・参照勾配・境界水深を
確認して再計算します。プロジェクト保存は別の操作です。

```csv
station,chainage_m,bed_elevation_m,roughness,x_m,elevation_m
S00,0,10,0.03,-22,18
S00,0,10,0.03,-10,10
S00,0,10,0.03,10,10
S00,0,10,0.03,22,18
```

この例は1断面だけなので単独では取込みできません。
[survey-absolute.csv](../examples/survey-absolute.csv) は11断面の**合成サンプル**です。
元の青葉川の台形断面を測量点形式にしたもので、現地測量や実務データを装っていません。
標高系に「合成サンプルの仮想基準高」、高さの解釈に「絶対標高」を選びます。

| 列 | 意味・制約 |
|---|---|
| station | 断面ID。1〜80バイト、制御文字なし。同一断面の行は連続 |
| chainage_m | 上流から下流へ増加する流下距離m。同一断面内で一致 |
| bed_elevation_m | 共通基準高の河床標高m。同一断面内で一致 |
| roughness | 断面全体のManning粗度n、0.005〜0.2。同一断面内で一致 |
| x_m | 局所横断距離m、各断面で厳密な昇順。垂直段差・重複は拒否 |
| elevation_m | 絶対標高なら河床標高を引く。相対高さならそのまま使用 |

2〜200断面、各3〜200点、全2000行以内、CSV 64 KiB以内。
固定ヘッダー・列順、数値は小数点 `.`、全て有限値が必要です。
UTF-8の先頭BOMと通常のCSV引用は対応。不正な引用・列数・欠損は拒否。
空行とフィールド外側の空白はCSVパーサーで除外します。
各断面の最低高さ0m、両岸は正の高さ。0.2.0では地盤の起伏を保持して取込みます。
計算水面が連続1流路となり、一意な限界条件と同じ水深範囲になる必要があります。
分離流路や一意な根がない条件は水理計算時に拒否します。[モデルと独立照査](irregular-sections.md)。
流下距離、間隔、勾配、断面幅変化もエンジンの入力検証を適用します。
値の丸め、並べ替え、補間、最低点の自動補正はしません。
絶対標高の減算にはIEEE-754の丸め誤差が生じます。

プレビューの診断には行・断面・項目・理由を表示します。区間全体のエラーは
行番号なしで表示します。エラーがある場合、部分的な断面を反映しません。
これは入力形式・形状の検証であり、指定した流量/境界で解が得られる保証ではありません。
河川中心線の座標、CRS変換、水平基準の一致、現地標高の正しさを自動照査する機能はありません。

反映時にプレビューの条件ハッシュを照合し、変更後の条件を古いプレビューで反映することを拒否。
施工案と累積段階をクリアし、古い結果とAI提案の表示を解除します。
取込み元のファイル名、元のUTF-8 CSVのSHA-256、取込みUTC日時、単位、高さの解釈を記録します。
標高系・水平座標の名称はプロジェクトに保存し、履歴・HTML・CSVの `reference_json` に含めます。
これは利用者が宣言したメタデータで、測量出典の認証ではありません。
元CSV自体はDBに保存しません。元ファイルを別途保管してください。
取込み後の編集は元CSVのハッシュを変えません。現在の条件は結果の再現用JSONと履歴で確認します。
従来のプロジェクトに基準高情報がなければ「未指定（プロジェクト内共通）」として読みます。

## 出典・利用条件の記録

CSVを選択した後、「出典・利用条件を記録」でデータ種別（未指定・合成・実測の申告）、
出典URL、出典・著作者、利用条件、測量日、変換・処理手順を記録できます。
不明な値は空欄にし、測量日を取込み日時で代用しないでください。
利用条件には条文の出典・版・必要な帰属表示を、処理手順には元ファイルの識別子/ハッシュ・
抽出した区間・単位変換・除外/補間と根拠を記録してください。元資料のファイルは別途保管します。

記録は任意です。未記録の項目をプレビューとHTMLに表示します。全項目の記入や「実測」の選択は、
配布元・ライセンス・標高系・測量品質をシステムが検証したことを意味しません。
情報の不足を根拠なく補いません。標高系・水平座標は従来どおり必須です。
出典の変更も確認トークンの照合対象に含め、プレビュー後の変更は再確認を要求します。
ブラウザで別CSVを選ぶと、前のファイルの出典入力はクリアします。

出典は `reference.import.dataset` に保持し、プロジェクト、通常/感度/測点間隔のSQLite履歴、
再現用JSON、通常CSVの `reference_json`、感度/間隔CSVの `project_json` に含めます。
通常/感度/測点間隔HTMLには読みやすい出典欄と未記録の診断を出します。保存履歴の出力は再計算しません。
古いプロジェクト/履歴の `dataset` 欠損は未記録として読み、数値結果を変更しません。
現条件の基準高等を編集しても取込み時の出典は変更しないため、変換・再取込みの履歴そのものを
自動記録する機能ではありません。測点間隔比較の履歴・成果は [専用仕様](station-spacing.md)を参照してください。

APIの `source` に任意の `dataset` オブジェクトを渡します。未記入の文字列は `""` です。

```json
{
  "data_kind": "unspecified",
  "source_url": "",
  "attribution": "",
  "usage_terms": "",
  "survey_date": "",
  "processing": ""
}
```

種別は `unspecified` / `synthetic` / `measured`。URLは認証情報のないhttp/https絶対URL（1000バイト以内）。
URLを自動取得する処理はありません。著作者1000、利用条件2000、処理手順4000バイト以内。
説明欄の改行/タブ以外の制御文字は拒否。日付は実在する `YYYY-MM-DD` か空欄です。
プレビューだけでなくプロジェクト保存・計算時にも出典を検証し、成果のHTMLは文字をエスケープします。

APIは `POST /api/imports/survey/preview` で `{csv,file_name,elevation_mode,unit,vertical_datum,horizontal_reference}` を受けます。
`elevation_mode` は `absolute` / `relative`、`unit` は `m` のみ。
`POST /api/imports/survey/apply` は `{source,project,confirmed:true,review_token}` を受けて
変更したProjectを返します。どちらも保存・水理計算は行いません。

# 感度比較

水理計算画面で流量または全断面粗度を選び、1〜8個の値をカンマ区切りで指定します。
基本条件から独立に計算し、境界水深・断面・河床・基準高を固定します。
基本条件に粗度の空間分布があっても、粗度の案は全断面を指定した値で置換します。
施工案はこの比較に適用しません。基本条件が計算できなければ比較全体を拒否します。
案だけが対象外/非収束なら、その案を理由付きの失敗として返し、成功案の結果は表示します。
失敗案の数値を補間・生成しません。条件を編集すると感度結果は解除されます。
ブラウザの比較操作は、条件・基準高・各計算の版・日時・失敗理由をSQLiteの感度履歴に追加します。
履歴を開くと保存時の比較を表示し、作業中の基本条件や保存プロジェクトは変更しません。
JSON・CSV・HTMLは保存結果から出力し、再計算しません。CSVは成功案の各測点の数値と基本条件からの
水位差を含み、失敗案は1行に変更条件・診断を記録し、数値や実行日時の欄は空欄にします。
HTMLは共通基準高の横断図・縦断水面形、数値表、失敗理由、手法・制約・出典・再現用JSONを含みます。
基本計算の失敗は履歴を作りません。基本計算が成功した場合、比較案がすべて失敗していても
診断の記録として保存します。感度履歴と施工比較の計算履歴は別々に管理します。

`POST /api/sensitivity` は `{project,cases:[{parameter:"discharge",value:100},{parameter:"roughness",value:0.035}]}` を受けます。
返り値は `{project,baseline,cases,note}`。成功案は `status:"ok"` とRun・水位差、
失敗案は `status:"failed"` と変更条件・理由だけです。保存プロジェクトと計算履歴は変更しません。

`POST /api/sensitivity/runs` は同じ入力をサーバーで計算し、保存した `{id,comparison}` を返します。
クライアントが計算済み結果を送って保存するAPIではありません。
`GET /api/projects/{id}/sensitivity-runs?before={cursor}` はプロジェクト別に新しい順で20件の概要を返します。
`GET /api/sensitivity/runs/{id}` は元の結果を、`/reports/csv` と `/reports/html` は保存結果の成果を返します。
再比較は新しい履歴を追加し、古い結果を上書きしません。SQLiteの再接続・オンラインバックアップ/復元・
負の数値のCSV保持・失敗案の空欄・ページング・ブラウザ再読込み後の出力を自動テストで確認します。
履歴の自動削除・容量上限・将来のスキーマ互換性は未実装です。
未保存の複製にもID別の履歴を作れますが、次回のプロジェクト一覧から選ぶにはプロジェクトも保存してください。
