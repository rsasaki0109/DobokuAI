# 感度比較の履歴・成果・復旧の検証 — 2026-10-11

流量/全断面粗度の独立した比較を、サーバーで計算して専用のSQLite履歴に保存します。
表示・CSV/HTML出力は保存結果を使い、元の条件・数値・版・日時・基準高・出典・失敗理由を保持します。
履歴を開いても作業中の基本条件や保存プロジェクトは変えません。
入力とAPIの仕様は [survey import / sensitivity](survey-import.md) を参照してください。

## 今回確認したこと

- SQLite再接続後、全浮動小数点数を含め保存時のJSONと完全一致。
- プロジェクトを編集しても旧結果は変わらず、保存結果の出力で新しい履歴を作らない。
- 基本計算の失敗とクライアント提供の計算結果は保存しない。
- 個別の失敗案は変更条件と診断を保持し、CSVの数値・実行日時・計算条件欄を空欄にする。
  すべての比較案が失敗した場合でも、成功した基本計算と診断を保存できる。
- CSVをPython標準`csv`で読み、負の標高・水位差・入力値を数値として保持することを確認。
- HTMLは共通基準高の縦断図と11地点の横断図、各条件の表、手法・制約と元の日時を含む。
  プロジェクト名・基準高のHTML特殊文字をエスケープする。
- CSV取込み元のファイル名・SHA-256を、感度履歴とCSV/HTMLでも保持。
- プロジェクト別の20件のカーソルページングは、新しい履歴が途中に追加されても重複しない。
- 稼働中WAL DBのオンラインバックアップを新規DBへ復元し、成功結果と失敗理由を完全一致で回復。
  従来DBも復元でき、壊れた感度JSONを含むDBは拒否する。
- ブラウザで再読込み後に作業流量を125m³/sへ変更しても、元の100m³/sの感度結果を開ける。
  JSONは元の結果と一致し、CSV/HTMLは元の日時を保持する。成果出力時にPOST/再計算はしない。

`bash scripts/check.sh` はfmt、clippy（警告をエラー扱い）、44 Rustテスト、3 Python復旧テスト、
独立RK4参照の再生成照合、TypeScript/製品ビルド、5ブラウザE2Eで成功しました。
履歴読込みの競合対策後、最終UIのビルドと5 E2Eを再実行して成功しました。
Docker配布版の今回の結果は [validation record](validation.md) に追記します。
