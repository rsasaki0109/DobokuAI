# 河川の試行記録パック

プロジェクト画面で、計算を実行するか既存の計算履歴を開き、「試行記録パック」を使います。
施工比較の計算履歴を基本として、感度比較・測点間隔比較の保存履歴を任意に選択し、
内容を確認してZIPを保存します。以前の比較履歴もページ単位で読み込めます。
ZIPを展開して`index.html`を開くと、各図付きレポート・CSV・保存JSONへ移動できます。
閲覧にDobokuAI APIやLLMキーは不要です。
PythonでZIPと保存JSONの収支を照査する[オフライン照査ツール](offline-audit.md)も利用できます。

## 同じ条件の成果を収録する

比較履歴には次の一致を要求し、異なる場合はZIP生成を拒否します。

- プロジェクトID。
- 全河川条件と`reference`全体（基準高・水平座標・取込み記録・出典を含む）。
- 保存されたエンジン版。
- 保存された基本計算の全数値と注意事項。

プロジェクトの表示名や施工案一覧は一致条件に含めません。
感度・測点間隔比較には施工案を適用しないため、基本の河川条件を比較します。
別のCSV取込み日時を持つ記録は、同じ座標値でも別の取込み記録として拒否します。
組合せを変更すると前の確認結果とZIP保存ボタンを隠します。
揃う履歴がなければ比較を省略した基本計算のみのパックも作れます。

成果作成は保存されたスナップショットを読み、数値計算を実行しません。
現在の作業条件・プロジェクト・全計算履歴を変更せず、履歴を追加しません。
最新プロジェクトを編集しても、旧履歴の条件・数値・計算日時で出力します。
元のエンジン版と、成果を出力するDobokuAIの版を区別して記録します。

## ZIPの内容

| ファイル | 内容 |
|---|---|
| `index.html` / `README.txt` | 収録履歴のID・元の計算日時/版・案数/失敗数・出典・各成果へのリンク |
| `manifest.json` | `doboku-review-pack-1`、パック生成日時、出力版、選択ID、条件・基本結果・各ファイルのSHA-256とサイズ |
| `conditions.json` | 元のRiverとreference。ファイル自体のSHA-256が条件識別ハッシュ |
| `construction.json` / `.csv` / `.html` | 保存計算・施工比較と同じJSON/数値データ/図付き成果 |
| `sensitivity.json` / `.csv` / `.html` | 任意の感度履歴。失敗案の理由と空欄の数値を保持 |
| `resolution.json` / `.csv` / `.html` | 任意の測点間隔比較履歴。元測点での差・補間条件・失敗を保持 |

基本のみは7ファイル、3種類の履歴を揃えると13ファイルです。
ファイル一覧に`manifest.json`自身は含めません。再出力時はパック生成日時が変わりますが、
同じ保存履歴と出力版なら収録成果のバイト列とハッシュは同じです。
ZIP全体やマニフェストのバイト一致は要求しません。
ハッシュはファイル識別用で、出典の正しさや測量精度を認証するものではありません。

原CSVの内容は履歴DBに保存されておらず、パックにも同梱しません。
取込み時のファイル名・SHA-256・出典と照合できるよう、元ファイルや
[取込み点検JSON](survey-import.md)を別途保管してください。
このZIPはプロジェクト読込みやSQLite復元用ではありません。[復旧手順](recovery.md)を参照してください。

保存結果から出力するCSV/HTMLには現在の成果生成コードを使います。
過去の別出力版で作ったCSV/HTMLとのバイト一致や、将来の別形式の互換性は保証しません。
パックに残る保存JSONの元条件・結果・版・日時は変えません。

## APIと制約

`POST /api/review-packs/preview`と`POST /api/review-packs/zip`へ、次を送ります。

```json
{"run_id": 1, "sensitivity_id": 2, "resolution_id": 3}
```

比較IDは省略または`null`も可。正の整数を要求し、存在しないIDは404、不一致は422です。
previewのファイルハッシュは同じ条件で生成するZIPのファイルと一致します。
各リクエストの生成日時は独立で、マニフェスト自身は比較用ファイル一覧から除外します。

ZIPは`zip 6.0.0`の非圧縮エントリーを使用します。
繰り返し条件を含むCSVの生成前に、条件サイズと出力行数から容量を保守的に見積もります。
64 MiBの予算を超える見込みなら拒否します。実際には64 MiB以内の成果でも見積もりで拒否する場合があります。
巨大なパックは比較履歴を減らすか、個別成果に分けて出力してください。値の間引きや部分成果の配布はしません。
同時成果生成も既存の処理枠で制限します。

この機能は試行資料の取りまとめです。実河川データの採用、独立照査、復旧、ホストCI、
人のレビューの完了を自動判定せず、成熟度にも自動加点しません。
実際の試行条件は[目標の必須条件](maturity-goal.md)に従います。

## 同梱CSVでトライする

APIを起動した後、リポジトリ直下で次を実行できます。Docker標準ポートの例です。

```bash
python3 scripts/try-review-pack.py --base-url http://127.0.0.1:8080 --output .local/review-pack-trial
```

出力先には新規または空のディレクトリを指定します。既存成果を上書きしません。
同梱の`examples/survey-absolute.csv`を合成データとして確認付きで取り込み、
固有IDのプロジェクトを作ります。既存プロジェクトは編集しません。
1m掘削・流量120/10000m³/sの感度比較・測点間隔2/4分割を実行して保存します。
13ファイルのCRC・サイズ・SHA-256、保存JSONと6個別CSV/HTMLとの完全一致、
失敗案の数値空欄、プロジェクトと履歴件数の不変を独立したPython標準ライブラリで確認します。

`sample.zip`、元CSVの`source.csv`、取込み点検の`source-and-preview.json`、
検証結果の`trial-result.json`を出力します。元CSVはZIPと別に保管します。
これは合成データの操作・成果検証で、実河川試行や人のレビューではありません。
2026-10-12のDocker版トライでは、掘削量約32,000m³、最大水位差約−0.316mでした。
