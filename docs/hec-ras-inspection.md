# HEC-RAS原入力のオフライン点検

`scripts/inspect-hec-ras.py`は、手元のHEC-RAS ASCIIプロジェクト・形状・定常流ファイルを点検します。
Python 3.11以上の標準ライブラリのみを使い、ネットワーク接続・外部HECプログラムは不要です。
原ファイルを変更せず、入力ファイル全体のサイズ・SHA-256を記録したJSONを作成します。

```bash
python3 scripts/inspect-hec-ras.py \
  --project /path/to/river.prj \
  --geometry /path/to/river.g01 \
  --flow /path/to/river.f01 \
  --plan /path/to/river.p01 \
  --output /path/to/new-inspection.json
python3 tests/test_hec_inspection.py
```

プロジェクトに列挙された形状/流量の拡張子と同じモデル名を要求します。
`--plan`は任意です。指定時はプロジェクトに列挙された同じモデル名の計画を要求し、
計画内の形状/定常流参照と渡したファイルを照合します。未指定の計画を自動選択・実行しません。
CLIは既存出力への上書きを拒否し、原入力と出力に同じパスを指定しても原ファイルを保護します。
各入力は8 MiBまで、形状レコード2,000個、表の1ヘッダー当たり5,000項目、流量プロファイル50個までです。
ASCII/UTF-8のみを受け付け、別エンコーディングの自動変換はしません。

## 確認する内容

- 原プロジェクトの`English Units` / `SI Units`宣言。宣言の欠落・重複を記録します。
  明示された単位名の記録に留め、測量の鉛直基準やUS Survey Foot等の実現を推定しません。
- 河川・区間・測点ラベルを区別した横断識別子、重複、原下流距離欄。
  数値に見える測点ラベルも、縦断距離へ変換しません。
- `#Sta/Elev`と`#Mann`の8桁固定幅数値表。全対象表の宣言件数、欠落・余分な項目、
  非有限値、横断距離の逆順を検出します。並べ替え・補正をしません。
  同じ横断距離の点は鉛直辺の確認事項として保持します。
- 複数の流量指定位置、原係数値の違い、合流・非横断レコード・無効流域ヘッダー。
  対象外条件を省略して単純な河川モデルへ変換しません。
- `#Mann`のヘッダー全欄と数値表の3列を保持します。補助欄の意味が未確認なので、
  値の違いを横断方向・鉛直方向の粗度変化やManning nの指定方式と断定しません。
  `native_coefficient_mode_requires_review`を明示し、変化があれば
  `native_coefficient_variation_present_mode_unconfirmed`を記録します。
  同じ断面に複数の表がある場合も、重複の指摘と元の各表を残します。
- プロファイル名はラベルとして保持し、実際の流量表を別に記録します。
  名前に含まれる数字を流量として採用しません。名前がある場合は列数・重複宣言を点検します。
- 河川・区間・プロファイル別の境界記録。`Up/Dn Type`は原整数コード、
  `Up/Dn Slope`と`Up/Dn Known WS`は原数値として保持し、重複・非有限値・識別子・不足を点検します。
  負の絶対水位をゼロへ補正しません。境界タイプの意味や未知の追加フィールドは解釈しません。
- 未対応の`Up ...=` / `Dn ...=`項目は`uninterpreted_fields`に原文字列・行番号を保持。
  関連する境界識別子がない場合は`unassociated_boundary_fields`に記録します。
  同じ未対応キーの重複も失わず、数値への変換・有限性検証をしていないことを確認事項にします。
- 指定計画の`Subcritical Flow` / `Supercritical Flow` / `Mixed Flow`宣言。
  宣言の欠落・競合、形状/流量参照の不一致、標準逐次/限界/最大誤差許容値と試行回数の非有限値等を点検します。
  混在流況は現在の計算エンジンの適用外として明示し、原設定をDobokuAIへ適用しません。
- 観測水位の欠損を`null`として保持。全プロファイルの列数・有限性を確認します。
  河川・区間・ラベルが一意に一致し、下流距離がゼロの場合だけ`at_section`と記録。
  非ゼロ距離は`downstream_offset_requires_review`、一致なしは`missing_section`、
  同じ識別子の形状が複数なら`ambiguous_section`とします。
- `BEGIN/END DESCRIPTION`内の文字列を構造データと区別します。
  説明欄に書かれた基準高・測点の文字列を正式な入力キーとして採用しません。

観測の距離欄は、[公式マニュアルのObserved WS説明](https://www.hec.usace.army.mil/confluence/rasdocs/rasum/latest/performing-a-steady-flow-analysis)
で「選択断面から下流への距離」と確認しました。
同じラベルでも非ゼロの距離は断面上の観測として直接比較できません。
ツールは観測位置の補間や水位誤差の計算をしません。

## 判定の意味と限界

終了コード0・`inventory_complete=true`は、対象の数値表/キーの点検に異常がなかったことを表します。
水理エンジンへの適合、原測量の精度、共通基準高、利用条件、校正・設計実務への適用は確認できません。
構文・数値の指摘があれば終了コード2とし、指摘付きレポートを残します。
入力サイズ・文字コード等で点検できない場合は、エラーを出して新しいレポートを作成しません。

`requires_review`は既知の確認事項です。HEC-RASの全構文・全オプション、断面の水理的適合、
無効流域の内容や局所損失のモデルを網羅した検証器ではありません。
粗度の補助フラグ、境界種別コードの意味、全計画オプションは解釈せず、SI換算・流量変更・横断抽出・CSV変換・計算は行いません。
計画の未指定や、境界の未記録/区間・プロファイルの不足は確認事項として表示します。
JSON形式は`doboku-hec-ras-inspection-3`です。形式1には計画・境界の点検結果がなく、
形式2には粗度の原ヘッダー/全3列と未対応境界フィールドの保持がありません。
以前の`transverse_coefficient_variation_present`は方向を断定し過ぎた分類でした。
形式3は方向・指定方式の未確認を明示し、以前の報告を自動変換しません。
`inventory_complete`は未対応項目の数値や意味を検証したことを表しません。
例えば未知の項目の`NaN`は原文字列で保持し、確認を要する未解釈項目と扱います。
`dataset_adopted=false`と`solver_input_generated=false`を常に記録し、指摘が少ないデータも自動採用しません。
原取得ファイルの利用条件は利用者が別途確認する必要があります。

## 検証

合成16テストで、全ファイルのハッシュ・無変更、空白で分離されない固定幅数値、異常件数/余分な点/非有限値、
横断距離の逆順と鉛直辺、区間識別と観測オフセット、重複識別子、流量・粗度・構造物条件の保持、
説明欄との区別、異なるモデルの拒否、サイズ上限、拒否結果の保存と上書き禁止を確認。
先頭16 KiBより後の非有限値も検出します。計画の不一致・競合流況・非有限設定、
未知の境界コード・負の水位の保持、重複境界/値・不完全なプロファイル対応、
プロファイル名と流量値の区別も確認します。`scripts/check.sh`のCIチェックへ追加しました。
粗度の補助欄が1 / -1 / 未知の値でも方向を断定せず、全3列・重複表を保持すること、
未対応境界項目・重複キー・識別子のない項目・数値に見える原文字列の保持も確認します。

取得済みの[Trinity原データ](public-data-hec-review.md)でも実行し、56断面・8,054点の数値表を点検。
観測位置は一致なし46、断面上15、下流オフセット付き4でした。
全56断面に原係数値の変化、26断面に無効流域ヘッダー、4か所に流量指定が存在することを再確認。
形式3の点検では56個の粗度ヘッダーと423行の3列数値表を保持。ヘッダーの末尾2欄はすべて`-1,0`でした。
その意味は解釈せず、原ファイルの指定方式を要確認とします。点検対象の未対応`Up/Dn`項目は0件です。
これは原入力の点検であって、Trinityの水理計算・現地照査・採用ではありません。
原計画`.p01`も点検し、形状`g01`・流量`f01`の参照一致、`Subcritical Flow`、3プロファイルの
境界コード3と勾配0.0023を保持。原計画の標準逐次/限界の許容値0.01、最大誤差許容値0.3、試行回数20を記録しました。
許容値は原数値であってSI単位への換算や、DobokuAIの収束条件を変更したものではありません。
