# 複数計画標高の断面積比較

2026-10-13。「都市・地形3D」で同じ確認済み元断面に複数の水平計画標高を設定し、
Rustの断面積計算を1件ずつ実行して切土/盛土の変化を比較します。LLMキー不要、Rust APIが必要です。

## 操作

1. 施工範囲・東西/南北断面を表示し、基準案の切土・盛土断面積を計算します。
2. 「比較する計画標高」に原データ基準のmで標高を入力します（例 `-1, 0, 1`）。
   半角カンマか改行で区切り、重複なしの1〜9個、有限値かつ±12000m。入力は2048文字まで。
   空欄、重複（0と−0を含む）、16進数、NaN/Infinity、範囲超過を拒否します。
3. 標高一覧と基準案を確認して「標高一覧を確認して断面積を比較」。
4. 入力順の全ケースを表と散布図で確認し、HTML/CSV/JSONを保存できます。
5. 成功した標高の「断面比較を表示」で、基準案と同じ座標・縦軸の2案断面図を表示。
   キャッシュした計算結果を使い、表示や保存のための再計算は行いません。

初期値は基準標高−1m/基準標高/基準標高+1mの範囲内の値です。
基準案・原地形・施工範囲・河川条件は変更しません。基準案は復元した個別案も使用できます。
全標高を順に計算し、途中の失敗を記録して次へ進みます。全ケースが失敗した場合も理由一覧を保存できます。
取消・入力編集・基準案変更・断面再表示・モデル置換は途中の要求を中止し、残る標高を実行しません。
部分結果を正常完了として出力せず、遅延応答で結果を復活させません。

## 数値と図

計算法は既存の[doboku-earthworkの区分線形積分](city-grading.md)。
同じ原断面・被覆判定・エンジン/モデル版を要求し、相違した返答はそのケースの失敗として記録。
各案−基準案の差を表示します。全長面積がnullの軸は全長差もnull/未算定で、既知小計差を別に示します。
失敗ケースには面積・計算日時・返答エンジンを捏造しません。

散布図の横軸は計画標高、縦軸はm²。全長が未算定の軸では、一意な区間だけの小計であることを明記。
赤が切土、青が盛土で、計算した点だけを表示します。失敗標高の点を置かず、点の間を補間しません。
表示用目盛りは桁をまとめますが、表・CSV/JSONの数値は丸めません。東西と南北は合算しません。

## 保存と再現性

`report_type:city_centerline_grading_sweep`、schema_version 1、`volume_calculated:false`。
JSON/HTMLに元断面・原点/CRS・元ファイルのbytes/SHA-256・出典/利用条件、基準案と全成功案の条件/区間結果/版/原計算日時、
指定標高順、失敗理由、断面点検日時と資料作成日時を保持します。
HTMLは画面と同じ表/散布図と同じCSV、全記録JSONを含み、通信・スクリプトなしで開けます。

CSVは各標高×各軸の概要行。未知/失敗の面積は空欄、既知の0は数値0。
数値の負の差はそのまま、文字列は既存の数式先頭保護を適用。原点・座標・条件・版・日時・出典も各行に保持。
区間別の全数値は全記録JSON、または選択案の2案比較CSVで確認できます。
選択案のJSONは既存の2案比較形式であり、[元断面とRust照合による確認付き復元](city-grading.md#保存した2案比較jsonを開き直す)を使用できます。
複数標高JSON自体の読込み復元・DB保存・自動最適標高選択は未実装です。

## 制約と検証

中心を通る2線と水平計画面の断面積です。全域のTIN掘削体積、法面、土質、締固め、建物干渉、
水理・構造・施工可否、費用/工期は未算定。均衡土量や最適標高と断言せず、欠損を補完しません。
原資料の測量精度、実河川の試行、現地校正として数えません。
[検証記録](city-grading-sweep-validation.md)。
