# 成熟度の到達目標 — 2026-10-11

**確定目標: 類似製品に対する成熟度60%。**
対象は「限定した河道改修業務で、技術者が独立照査付きで試行できる製品」です。
2026-10-11、ユーザーが「60%：限定業務で試行できる製品」を選択しました。
目標確定時は約30%でした。目標設定だけでは値を上げず、現在の評価は [development status](development-status.md) に記録します。

## 60%を最初の目標にする理由

現在のMVPから進めるには、実データを読み込み、計算を照査し、施工案の比較と成果出力を
完了できることが重要です。60%はその一連の業務と試行に注力する到達点です。
80%を目指す段階では、試行で分かった問題に加えて、継続した運用・配布・互換性・
サポートの実績も必要になります。先に試行結果を得ることで、追加する機能と運用を判断できます。

今回の対象業務は、対応範囲内の1D定常流における横断面編集、河道掘削/断面変更、
粗度・流量の検討、水位/土量比較、履歴と成果出力です。
跳水・混在流況・越岸・構造物損失・非定常流等は引き続き対象外と明示します。
道路・橋梁・砂防・工費/工期の自動推定は、この目標の達成条件に含めません。

## 中間目標

| 到達点 | 意味 | 必要な証拠 |
|---|---|---|
| **約40%** | 数値照査と実データ取込みの基礎ができる | 非一様な射流/測量断面等の独立参照、刻み幅収束、誤差記録。横断測量CSVの読込・入力診断・プレビュー |
| **約50%** | 社内検証で一連の検討が完了する | 複数の実務相当データで取込み→条件変更→施工/感度比較→照査→成果出力→履歴復元。CIとバックアップ/復元を実行確認 |
| **60%** | 技術者が独立照査付きで試行できる | 下記の必須達成条件をすべて満たし、利用者の試行と結果を記録する |
| 将来の候補 **80%** | 商用提供の可否を判断できる材料を揃える | 試行の問題解消、配布・互換性・継続運用・サポートの証拠。提供形態に応じた権限、契約・ライセンス等の整理 |

表示値は評価結果から5%刻みに丸めます。各段階は追加した機能の本数で自動達成とはしません。
80%になったことだけで商用利用や設計実務への適合が保証されるわけではありません。

## 60%の必須達成条件

| 条件 | 完了判定 |
|---|---|
| **数値の独立照査** | 矩形・台形・対応する測量断面、非一様な常流/射流について参照ケースを整備。入力・境界・基準高・粗度・手法を記録し、事前に定めたケース別の誤差条件と刻み幅収束を満たす。少なくとも一つの外部の独立した解析手段/参照結果とも照合する |
| **実データの取込み** | 単位、流下距離、絶対/相対標高、基準高、粗度を扱う横断測量CSVを読める。確認前のプレビュー、欠損・重複・非有限値・対象外断面の診断があり、黙って補正しない |
| **対象業務の完了** | 少なくとも3件の異なる実務相当データで、取込みから施工案比較・成果・履歴復元まで完了し、各データの出所と利用条件を記録。匿名化された実データまたは利用可能な公開データを用い、既存の合成サンプルだけで達成としない |
| **試行レビュー** | 独立照査を行える土木/水理技術者によるレビューを記録。目安は開発担当以外の技術者2名。入力の意味、計算の制約、比較結果、レポートを確認し、試行を阻害する問題を解消する |
| **再現性と復旧** | 実行条件・結果・エンジン版・日時を保存し、編集後も旧結果を復元できる。SQLiteのバックアップ/復元を実行検証し、CIと配布版で必須チェックを確認する |
| **AI操作の確認と失敗処理** | ローカルの型付き操作がキーなしで動き、確認前に条件を変更しない。失敗時・異常応答時の条件と結果の扱いを検証。外部LLMは契約テストを用意し、実通信の未検証部分を明示する |

データ数・レビュアー数は試行の目安であり、現地校正や設計認証の代わりではありません。
外部の参照結果は出所と計算条件を記録し、比較するモデルの適用範囲を一致させます。
実際の許容誤差はケースの条件・解法・離散化を踏まえて定め、実行結果を見て都合よく緩めません。

## 同じ採点基準での目標像

[product research](product-research.md) の重みと段階を維持します。
以下は到達を目指す評価の組合せで、将来の実測結果ではありません。

| 観点 | 重み | 目標確定時 / 5 | 目標像 / 5 | 目標加点 |
|---|---:|---:|---:|---:|
| 数値モデル・適用範囲 | 25 | 2.0 | 3.0 | 15.0 |
| 数値検証・照査 | 25 | 1.0 | 3.0 | 15.0 |
| データ連携・座標/基準高 | 15 | 0.5 | 3.0 | 9.0 |
| 編集・施工比較・成果・再現性 | 15 | 2.5 | 3.5 | 10.5 |
| 配布・運用・保守 | 15 | 1.0 | 3.0 | 9.0 |
| AIの操作支援 | 5 | 2.0 | 2.0 | 2.0 |
| **合計** | **100** | **29点** | | **60.5点（表示60%）** |

達成判定は **丸める前の採点が60点以上、かつ必須条件がすべて完了** したときです。
他の点数で補って数値照査や試行を省略する達成判定はしません。
数値モデルの評価を上げる証拠は、対応範囲内の実務相当ケースを扱えることであり、
未検証の物理モデルを追加することではありません。
AIの目標像は現在と同じ段階を置き、外部LLMの実APIキーを60%到達の必須条件にしていません。

## 開発を進める順序と依存関係

1. 数値照査の拡充と横断測量CSV/基準高の仕様・実装。
2. 複数データで施工比較・感度比較・成果出力を検証し、不具合を修正。
3. CI、配布版、履歴、バックアップ/復元とAI操作の失敗処理を検証。
4. 技術者の試行とレビュー結果を記録し、達成条件を評価。

開発と自動テストは自律的に進められます。実データの利用許可と技術者のレビューは、
実際の協力と証拠が必要です。開発担当がそれらを実施済みと代用して60%と報告しません。
この計画は外部への連絡や利用者の募集を指示・実施したものではありません。
納期は未設定です。データの入手と試行体制を確認する前に期間を断定しません。
