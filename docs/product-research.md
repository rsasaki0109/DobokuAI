# 類似製品調査と DobokuAI の成熟度

調査日: **2026-10-11（JST）**。対象は現在の河川エンジニアリング製品です。
道路・橋梁・砂防を含む将来の全プラットフォームは今回の採点対象に含めません。

**現在の評価: 既存の実務向け河川製品の水準を参照した DobokuAI の成熟度は約45%。**
限定した河川 MVP は動作しています。実務で扱うデータ、照査できる計算条件の幅、
運用・保守の証拠がまだ少なく、成熟した解析製品の代替を主張できる段階ではありません。

これは独自の重み付き評価です。市場統計、ユーザー満足度、計算精度の比率ではありません。
製品をインストールした比較試験や利用者への聞き取りは実施していません。
初回調査として20〜40%程度の見積もりの幅があり、これは統計的な信頼区間ではありません。

## 調査方法と確認範囲

開発元の公開 GitHub 資料、iRIC の操作マニュアル、DHI の連携ライブラリ、
Deltares の製品説明を実際に取得して読みました。取得した原文と SHA-256 の記録は
作業環境の `.local/research/` に置いています。第三者の説明を公式仕様として扱っていません。

HEC-RAS の公式機能ページは、通常のプロキシ経由のアクセスで `403 Forbidden` となり未取得です。
HEC の公式 GitHub 組織は閲覧できましたが、これだけで現行 HEC-RAS の機能一覧は確認できません。
以下では HEC-RAS の一般的な既知仕様を背景情報として示し、一次資料を確認した製品とは区別します。
全製品の最新リリース、販売価格、ライセンス契約全文、現場実績件数は調査していません。
GitHub の開発ブランチは製品の最新安定版と同一とは限りません。

## 成熟度の評価基準

100%は、対象の河川業務について継続利用できる解析・データ・照査・運用の水準です。
比較対象の全機能を合併した巨大な機能一覧を100%とするものではありません。
すべての製品を同じ環境で採点した順位表でもありません。

各観点は0〜5で評価し、必要に応じて0.5刻みを使います。

| 段階 | 証拠の目安 |
|---:|---|
| 0 | 未実装、または動作証拠がない |
| 1 | サンプル・限定した試作・一部の検証がある |
| 2 | 限定した対応範囲で一連の操作が動作し、基本検証がある |
| 3 | 複数の実務相当データ、独立照査、対象業務の完了を確認できる |
| 4 | 利用者の試行、回帰検証、復旧・配布・互換性を継続管理している |
| 5 | 対象業務で繰り返し利用され、検証・保守・サポートの証拠が蓄積している |

| 観点 | 重み | 評価 / 5 | 加点 | 判断理由 |
|---|---:|---:|---:|---|
| 数値モデル・適用範囲 | 25 | 2.0 | 10.0 | 限定した1D定常流が動作。実務対象の幅は小さい |
| 数値検証・照査 | 25 | 2.5 | 12.5 | 独立参照6ケースに加え、外部SWASHESの矩形B1常流/射流で条件正規化・外部河床/計算の細分化・固定参照再生成を確認。実測・利用者照査は不足 |
| データ連携・座標/基準高 | 15 | 2.0 | 6.0 | CSV診断→確認→反映→基準高/取込み元記録→成果/保存をAPIとブラウザで検証。実河川データの利用実績とCRS変換は不足 |
| 編集・施工比較・成果・再現性 | 15 | 2.5 | 7.5 | 一連のMVP操作と履歴が動作。感度/測点間隔比較も元の条件・数値・日時・失敗理由で履歴/CSV/HTMLを出力・復旧できる。実務相当の利用確認にはまだ届かない |
| 配布・運用・保守 | 15 | 2.0 | 6.0 | 稼働中WALとCompose volumeの別volumeへの復旧・同一履歴/成果の回復、配布ビルドの機能を確認。ホストCI実行・継続運用/配布管理は未確認 |
| AI の操作支援 | 5 | 2.0 | 2.0 | 確認付き型付き操作は動作。外部プロバイダと実務での有用性は未検証 |
| **合計** | **100** | | **44.0** | **表示値は5%刻みで約45%** |

数式は `Σ（重み × 評価 / 5）`。テストの本数やソース行数は成熟度そのものではありません。
表示は過剰な精密さを避けるため5%刻みとし、新しい証拠がない回答では同じ値を維持します。
モデルの誤差を測った値とこの成熟度を混同しません。改善や再評価で下がる場合もあります。

以前の **MVP完成度88%** は、最初に指定した機能と開発チェックを中心とする内部の進捗見積もりです。
初回の製品調査では実務向け製品としての証拠まで含めたため、同じ実装でも約30%という評価でした。
今後の対話末尾の主指標はこの「類似製品に対する成熟度」とし、分母を途中で変えず更新します。

当面の到達目標は50%の社内評価版です。技術者レビューを伴う60%は将来目標とし、
各目標の必須達成条件は [maturity goal](maturity-goal.md) に記録します。

## 開発への示唆と優先順位

当面の対象業務は **河道改修案の比較・照査・説明・履歴をまとめるAIワークスペース** が適切です。
これは今回の差分からの提案であり、市場調査や利用者ヒアリングで実証した需要ではありません。
AI提案を結果説明と決定論的計算に接続する構成を育て、対応する水理条件を明示します。

| 順序 | 次の開発 | 完了の証拠 |
|---:|---|---|
| 1 | **独立した数値照査の拡充** | 非一様な常流/射流、測量断面、断面変化について、参照解・刻み幅収束・流況・境界・残差を記録。既存製品との比較は両者の適用範囲が一致した条件だけで実施 |
| 2 | **横断測量CSVの読込と基準高管理** | 流下距離、断面点、絶対/相対標高、粗度、単位・基準高をプレビュー。欠損・重複・非対応形状を明示し、確認後に取り込む。読込から成果出力までE2Eで検証 |
| 3 | **粗度・流量・施工案の感度比較** | 検討範囲と変更条件を記録。非収束/対象外案を明示し、条件・結果・履歴を照査できる。根拠のない費用・工期は生成しない |
| 4 | **運用と利用者による試行** | CI実行、SQLiteバックアップ/復元の検証、配布版の確認。共有運用を始める場合は認証・権限。実務相当のデータで利用者レビューを受ける |
| 5 | **外部LLMと操作支援の検証** | モックを含む契約テスト、通信/JSON異常、未確認操作の拒否を検証。実通信の確認は設定されたキーがあるときに別途実施 |
| 将来 | 非定常・ネットワーク・構造物等 | 要求と検証計画を先に定義。外部エンジンとの接続も検討し、検証されていないモデルを設計対応済みと表示しない |

既存製品のモデル接続やコード利用を選ぶ際は、形式・実行環境・該当ライセンスを確認します。
MIKE+Pyが公開ライブラリでも、READMEには有効なMIKE+ライセンスが必要とあります。
Delft3D の多くのエンジンは GPL/AGPL、ユーティリティは別ライセンスです。
今回、外部コードの取り込みやDobokuAIのライセンス変更は行っていません。

## 測点間隔履歴・Compose復旧の追加 — 2026-10-11

測点間隔比較の全条件・結果・診断・出典・版・日時をSQLite履歴に保存し、再読込み後も
再計算なしでJSON/CSV/HTMLを出力できるようにしました。[仕様](station-spacing.md)。
[Composeの別volumeへの復旧](recovery.md)を実行し、12履歴・24成果の完全一致と
