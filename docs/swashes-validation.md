# SWASHES による外部数値照査 — 2026-10-11

公開された外部ツール **SWASHES** の定常解析例と、DobokuAIの標準逐次計算を照合しました。
自作RK4とは異なる出所の数値参照です。対象は有限幅矩形断面が緩やかに縮小・拡大する
MacDonald pseudo-2D B1 の常流・射流2例です。跳水や遷移流は含みません。
この照査は現地観測との校正、実河川の試行、設計認証を代替しません。

## 配布・固定条件

- [Python配布 swashes 1.5.0](https://pypi.org/project/swashes/1.5.0/) のLinux x86_64 wheelを取得。
- 実行ファイルの表示は `SWASHES version 1.05.00, 2025-04-22`。
- wheel SHA-256: `14a1d359c9baa8b21ce384180fee21b47e42818c1092d8a7dedd4d2a0158607c`。
- 実行ファイル SHA-256: `dbebe68fb9f26df4bcc4ca88ff8e4aafb78ba26750a64b86e423f7beeaaf4b24`。
- 関連文献: Delestre et al., SWASHES, [DOI 10.1002/fld.3741](https://doi.org/10.1002/fld.3741)。論文本文は今回未取得。

数値データ、実行引数、標準出力全体のSHA-256、正規化条件を
[swashes-reference.json](../examples/swashes-reference.json) に記録します。
生成器 [swashes_reference.py](../tests/swashes_reference.py) はRustエンジンを呼びません。

配布メタデータは `CECILL-2.0` を指定しています。[SPDXの標準条文](https://spdx.org/licenses/CECILL-2.0.html)
全体を確認し、5.1の実行・検証の利用許諾に基づき、外部開発ツールとして実行しました。
wheel内に元ライセンスファイルは含まれておらず、メタデータと標準条文の確認を区別しています。
外部バイナリは無視対象の `.local/` に置き、製品・Docker・リポジトリに同梱しません。
上流ソースは取り込まず、参照数値と独自の変換器・テストを保存します。製品のライセンスは変更しません。

## モデル条件を合わせる変換

SWASHESの例題は長さ200m、流量20m³/s、Manning粗度0.03、重力9.81m/s²。
幅は `B(x)=10-5 exp[-10(x/200-0.5)²]`、潤辺は `B+2y` として比較します。
1Dの別例題には幅広水路の近似があるため、有限幅を使うこの2例を選びました。
重力は同じ固定バイナリの1D出力でも確認しました。引数 `1 2 1 4 501` の先頭点は
`h=0.7415138, u=3.371482, Fr=1.250048` で、`u²/(Fr²h)` は表示丸めの範囲で約9.81です。
この1D例は重力の確認に使い、有限幅エンジンの直接比較例には数えません。

DobokuAIは重力 `g=9.80665` を使用します。エンジンは変更せず、比較入力を次のように正規化します。

```text
Q_engine = 20 × sqrt(9.80665 / 9.81)
n_engine = 0.03 × sqrt(9.81 / 9.80665)
```

これで `Q²/g` と `(nQ)²` が保たれ、水深に対するエネルギー・Froude・摩擦の式が一致します。
元の流量・粗度をそのまま入力した比較とは区別します。流速は流量比に応じて変わり、
SWASHESの元の20m³/sの流速との一致は主張しません。

出力のセル中心177点を抽出し、先頭と末尾の間を共通の比較区間にします。
常流は最後、射流は最初の参照水深を境界とし、x=0/200の境界へ外挿しません。
断面の堤岸高8mと等流水深診断用の参照勾配0.01は変換器の設定です。
堤岸内で解が存在することを確認し、これらを原例題の測量条件とは扱いません。
標準出力の表示精度による丸め誤差も残ります。

## 外部の河床出力と計算の細分化

探索時の193セル出力を直接使うと、常流で約0.01mの差が出ました。
SWASHESの河床出力がセル数に依存することを確認し、許容差を緩めず、外部側を細分化しました。
193点での探索後、177点の固定参照を生成する前に次の基準を設定しました。
完全な事前登録研究ではなく、探索と固定参照による回帰検証を分けた開発照査です。

- 外部河床の細分化差: 5×10⁻⁶m以下。
- DobokuAIの177点における最大水深差: 10⁻⁴m未満。
- 共通45点の水深誤差: 45→177点で4倍以上改善。

SWASHESを362,673セルと725,169セルで実行。177の奇数倍なので共通セル中心を正確に抽出できます。
同じ位置・同じ参照水深の出力を確認し、河床差は常流3×10⁻⁶m、射流4×10⁻⁶mでした。
これは2段階の細分化差であり、厳密な誤差上限とは扱いません。
DobokuAIは同じ河床・幅の部分集合45/89/177点で計算し、境界と比較位置を保ちました。

| 流況 | 45点の最大水深差* | 89点の最大水深差* | 177点の最大水深差* | 177点全体の最大水深差 |
|---|---:|---:|---:|---:|
| 常流 | 3.4275880×10⁻⁴m | 8.1425807×10⁻⁵m | 2.1666711×10⁻⁵m | 2.2603638×10⁻⁵m |
| 射流 | 3.0891829×10⁻⁴m | 7.6926740×10⁻⁵m | 1.9300960×10⁻⁵m | 1.9998214×10⁻⁵m |

*細分化比較は同じ45地点で評価。改善は約15.8倍/16.0倍です。
全測点の有限値・流況・区間エネルギー残差10⁻⁷m未満・境界水深の保持・水面標高も検証します。
計算の残差が小さいことと、参照水深との誤差が小さいことは別々に評価します。
水理エンジンのアルゴリズムや重力定数は変更していません。

## 再現

保存済み参照との数値比較は通常のCargoテストに含まれ、外部ツールやネットワークを必要としません。

```sh
bash scripts/run-cargo.sh test --locked -p doboku-hydraulics --test swashes -- --nocapture
```

外部参照の再生成照合はLinux x86_64とPython3.11以上で行います。
取得先は固定wheel、TLSとプロキシを維持し、wheelと実行ファイルのハッシュを確認します。
`--check` は保存済み参照を上書きしません。

```sh
python3 tests/swashes_reference.py --download --check
# 取得済みツールならネットワークなしで再照合
python3 tests/swashes_reference.py --check
```

クラウド上で固定ツールによる生成・再照合とRustの2ケースは成功しました。
GitHub Actionsにも再生成照合を追加しましたが、ホストCIの実行確認はまだありません。
今後は利用条件と座標を確認できる実河川データ、観測との比較、技術者による独立照査が必要です。
